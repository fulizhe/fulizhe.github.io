没有权力的逆淘汰组织里，怎么把自己捞出来

2026-08-06T15:41:27.000Z2026-09-05T02:48:25.202ZChina

1. 误诊：缺人不是病，黑盒和真空才是

今天上午和测试主管在群里聊起一件事。他说自己忙不过来、人都要废了，CI/CD 这块只有XXX一个人会，XXX一出差团队就瘫，想“放开口子”看看有没有人感兴趣来当备份。

我当场就觉得这个方向歪了。

累死的解法从来不是“找个人分担”，而是把“只有他知道”这件事本身消灭掉。

把问题定义成“缺备份人”，等于把症状当病治。真因有两层：

  • 流程黑盒化：CI/CD 链路只有XXX一个人走通过，这是典型的单点故障。
  • 判定标准真空：领导缺乏产出判定标准，只能看汇报，于是能干的人被无限加码，混日子的人舒舒服服——这就是我之前写过的逆向淘汰。

找新人来顶，无非是把单点故障从XXX平移到新人身上。新人要么变成新的守门人，要么被榨干后走人，三个月后回到原点。

2. 加人没用：反向筛选与单点平移

“兴趣是最好的老师”这句话，在逆淘汰组织里是反向筛选。

有兴趣、肯下功夫的人，恰恰是最快看穿“在这耗着不值”的人。YYYY说“总不能大家都不感兴趣就我们天天积极”——错，真相是：感兴趣的人留不住，留得住的是刷视频打游戏的。靠兴趣招备份，招来的要么三个月走人（你白培养），要么本来就不是你要的人（来了也是个不粘锅）。

这点我原话说过：“有兴趣的不会在这里待很久……这才是最大的症结。”

更阴的一层是鞭打快牛。公司默认规则是“干的越快、干的越多、干的越烂；干的越少，闲的闲死”。如果真教会新人且他变高效，系统会立刻把更多活压过来——结果不是减负，是你俩加新人三个人一起忙死。所以”放开口子”如果不配套”对外降频、对内白盒化、把兜底角色交还制造问题的人”，等于给自己新接一条救急链。

3. 我们早建了白盒，但没人用

必须说句公道话：白盒这步我们早就做了。

我和YYYY私下挤时间，用两个 jQuery 页面把流程串了起来——一个是所有产品的制品下载页，一个是所有产品的 Jenkins 打包流程页。这两个页面干掉了一个专门的打包岗，测试现在自己需要版本就自己打包、自己部署，全程没有研发参与。这整套动作，就是“黑盒变白盒、流程做成按钮”的标准答案。

但有个刺眼的事实：大部分研发至今不知道 jenkins 流程在哪、包怎么打出来，部分流程还是在群里@陈等十分钟。

白盒建好了，采用率是零。

根因不是技术门禁——我们内部系统甚至没有权限设置，因为有信心没人会主动想着去碰。门从来没锁过，连门都没锁都没人推。所以障碍从来不是 access，是 incentive。“@陈等十分钟”是零成本的旧习惯；走你建的页面要学、要动脑子，是正的成本。你不禁用@陈、不强制走页面、不把“自助”写进任何人的交付标准，白盒就是个摆设。

建了系统，没关老通道，也没写进任何人的 KPI——受益人永远选阻力最小的路。

4. 治本：把不可替代性从人变成系统

《黑盒之殇》里我写过一句结论：“当你把流程做成一个按钮时，任何人都能成为专家；当你把流程锁在脑子里时，你就是唯一的瓶颈。”

但这次我得补一刀：在逆向淘汰组织里，“教别人后解脱”这个前提不成立——因为没人想被教。apathy 会把白盒吃掉。

所以真正的治本是两步，顺序不能反：

  1. 把不可替代性从人变系统：白盒 + 指标，让流程不依赖任何具体的人。
  2. 再把系统负载按指标压回制造问题的人：谁家孩子谁抱走，对外降频惜身。

这不是”多找人”，是改结构。依赖从人身上卸下来，焊进系统和指标里，从此不需要任何人当钥匙。

为什么”靠自己”是被逼出来的，而且长歪了就是陷阱

上面两步解决的是”不被人卡脖子”。但有人会问：凭什么连成长的事都得自己扛？答案藏在组织侧的账本里——这类公司的特点，是只用不培养，成长完全靠自己。

这不是老板懒，是一个算得清的账。培养的 NPV 为负。 组织能定价的只有工时，定不了 merit。你花本钱把人养出来，他要么开口要加薪（组织不给），要么看清 dysfunction 走人（组织白养）；就算留下来，”鞭打快牛”把多出来的产出一次性榨干，不产生复利。所以”不培养”不是疏忽，是组织对自身 broken incentive 的理性适应——它根本没有捕获培养回报的能力。

顺下来就是单边抽取：你自掏成本长出的能力 Δ，组织对你的边际成本约等于零，却把 Δ 全收进产出、按原工资结算。 你薪酬不随 Δ 涨，自学的 ROI 为负，除非离职去一个能定价 merit 的市场。结论冷但干净——自学只在”离开”这个动作上才兑现价值。 组织早已把自己从”成长合伙人”位置上摘了出去，你被迫 solo 经营自己。

但”靠自己”是这局里你唯一的占优策略，陷阱也正在于长在哪儿：

  • 长进组织的上下文里（某 Jenkins 只有你会打、某黑盒只有你通）→ 你的成长变成组织的免费抵押物，不增加你的市场价，只增加”可榨取度”和”沉没成本”。你越在岗位上长，越被惩罚，越走不掉。
  • 所以”成长必须长在自己身上”的真正落点是一刀：把成长刻意留在可带走的寄存器里——判断力、可泛化的技能、声誉、网络。 别让组织把你的自投资源，转换成它独占的单点依赖。

之前说”把不可替代性从人变系统”，是防组织抽我；这一刀是让我的成长天生 portable，组织抽不走。前者守，后者攻。

（一处收口：NPV 为负不能一刀切。很多中小企业老板是真不会培养（生存型管理者），不是”算过账不愿”。能定价 merit 的组织，培养 NPV 为正，好公司才培养；不能定价的，不培养是宿命。所以”不培养”精准锚定在”逆淘汰 / 无 merit 定价”这个根上，不是泛化为”公司都烂”。）

5. 古德哈特：指标必被玩坏，那就轮动

前面说的“指标”，有个绕不开的坑。任何被观测到的统计规律，一旦施加管控压力、用作考核目标，它就会失效、崩塌——这就是古德哈特定律（Goodhart’s Law）。

禅道指标现在被领导当衡量标准，三年内必被“消费者心态”的人玩成表演：为了指标好看刷低价值动作，把水搅得更浑。我有心理准备。

我的对策是顺势而为、先动起来，等一个指标快被玩坏时，再建下一个指标轮动对冲。不指望单一指标长治久安，用指标轮换对抗博弈。唯一提醒自己的是：别等扭曲显现才建下一个，要在第一个还没烂透时就 preemptive 铺第二个——逆向淘汰组织里，博弈速度比你写指标快。

6. 消费者与投资者：指标是给混日子的人上的枷锁

我写过一篇《从消费者到投资者》：不少人来职场是“消费”来的，目的就是混满八小时。

这把“指标化”的作用说清了：

  • 指标只绑得住“消费者”（混八小时的人）——他们没自驱，只能靠外部指标勒住。
  • “投资者”（自驱的，比如我和YYYY）根本不需要指标——但恰恰是这群人，被负载二次收割，因为系统把消费者甩出来的活全压给了能干活的人。

所以整个对策的闭环是：用指标把消费者的水搅回他们自己锅里，投资者得以抽身。白盒化 + 指标化不是给你们加枷锁，是给消费者上的枷锁、给投资者开的门。

而投资者之所以必须自己长、且长可带走的那部分，根子正是组织是纯消费者——它只 burn 人、不 appreciate 人。这条账本，详见第 4 节末尾。

7. 没有行政权力，就借势

最后一个、也是最现实的问题：我们全是兼职，没有正式坑，更没有行政权力。”关闭@陈、强制走白盒”这种真正要命的事，靠什么推力？

答案是借，不是命令。

YYYY曾在群里绝望地问：”难道就认命，这工作真的要累死人的？”我的回答是：”肯定不认！不让我试？这不是因为你们丫的不动吗？否则能轮得到我？“

这片盐碱地虽然荒凉，却孕育着一种特殊的变革契机——危机借势（Crisis Leveraging）。

平时你跑去跟研发、管理层推规范化、容器化、CI/CD 卡点，他们不仅不配合，反而嫌你”没事找事”。但当”月度测评 / 线上故障”这种所有人集体抓狂、手忙脚乱的危机时刻降临，就是你唯一的黄金窗口。

趁他们手忙脚乱的热乎劲，把你想落地的东西当成”救命药”强行喂下去；等热度一过，立刻用流水线卡死，绝不让他们拖回泥坑。

具体三招：

  1. 痛点就是切入点。 平时他们嫌你烦，测评一来全被卡得生不如死。趁热把容器化、自动化流程当救命药喂进去。
  2. 用老板的焦虑借力打力。 领导因测评焦头烂额、急于找抓手时，顺理成章把”P1 下压””禅道硬性度量”递上去——你不是在推流程，是在帮领导解围。
  3. 封死退路，绝不妥协。 方案一旦在危机中落地，就用流水线卡死。绝不能等热度一过，又被老油条把流程拖回泥坑。

我们这次就是这样落地的：测试先吃白盒（可控）→ 研发被反向压回压力 → 指标沉淀出证明 → 领导见鬼子拉线、自上而下强制。YYYY是测试主管，测试是现成联盟；研发是待分化的抵抗方。领导属于”不见鬼子不拉线”的主——他不会为你的苦劳动，只会为已落地的好处动。

把测试这面”联盟”真正用起来，靠的是一条不能含糊的边界纪律：测试只反馈问题，不替研发做决策。 研发跑来问”这样决策行不行”的时候，一句话顶回去——“去找领导确认”。测试不负责解决，也不背这个责任；如果研发坚持认为合理，让领导来跟测试确认，并且全程留痕。职责清晰是最基础的职场要求，搅和在一起就是过往最大的症结：测试就是不该关心”为什么”，只看结果——通过了就通过，挂了就挂了，把判断权交还给该做决策的人。你越替他们兜决策，他们越把这当成你的活；你把它推回给领导、钉死在结果上，铁桶才筑得起来。点播要轻、要借势——平时说，她们当那是嘻嘻哈哈的闲话；真到月度测评或线上故障的危机窗口，你喂进去的东西才立得住。所以顺序不能反：先有测试采纳 + 指标证明（bottom-up），再把战果递上去，他才乐得摘桃推行。

唯一的残余风险：从”测试采纳”到”领导拉线”这段证明期，额外负载是你俩扛的。所以”借契机”不是调料，是防 burnout 的催化剂——它加速领导拉线，让你少扛一段。

8. 一道已闭环的防火墙（可观测性）

顺便说一嘴可观测性，因为它常被误读成“组织透明化革命”——在我这它不是。

我在自己负责的那部分系统内部建了一整套可观测体系，目的也只是、且只能是：保证自己这边不被研发把锅甩过来。

旧玩法很脏：研发指挥你“去查 XXX”→ 你在那查 → 他报工写“协助调查 XX”显得劳苦功高 → 出问题反手一句“XX 你们还在分析，我们才能解决”。这是一鱼两吃：既白嫖你的排查劳力，又把锅的归属锚在你“还没分析完”上。

现在“你要的信息就在这”——这条通道被焊死。研发不能再以“等他们分析”为借口躲在后面，也不能再把排查包装成自己的协助工时被领导看见。这道防火墙是双向的：它既防甩锅，也反向逼研发自己动起来。

但边界我划得很死：它是产品内部、仅覆盖我自己那部分的护城河，不是整个流程的透明化，不解决 CI/CD 单点，更不解决组织逆淘汰。它自认已经做到单体应用极限，闭环了，不当主线讨论。它最多是杠杆线里的一个注脚：先把自己打成铁桶。

（顺带一句，研发曾想拿”监控拖慢交付”当接口反制——在我们这种内网 ToG 系统里 99% 谈不到性能；监控可在线关闭，且多次救火立功，他们现在不敢疑了。）

9. 两条线：防火墙 + 杠杆

收口成一条干净的判断：

线 状态 内容
防火墙线 已建（闭环） 产品内可观测，防甩锅 + 双向逼研发自检
杠杆线 仍在推 CI/CD 白盒化 + 部署成功率 + 禅道指标 + 分化测试（测试只反馈不决策、推给领导确认留痕） + 借势领导

防火墙只灭“拖你下水”，不灭“XXX单点瘫”——所以 CI/CD 白盒化仍是独立的待推项，和防火墙两码事、互不替代。

后记

回头看这场讨论的起点，其实是个红鲱鱼。

群聊里真正刺痛人的，是“XXX一出差我们就瘫”。但瘫的根子不在XXX本人，在他头顶那套结构：流程黑盒化让依赖长在了人身上，判定标准真空让混日子的人甩锅零成本，逆向淘汰让能干的人越干越多直到废掉。

所以解法从来不在“找个人顶上”。把不可替代性从人变成系统，再把负载按指标压回制造问题的人——没有行政权力，就 bottom-up 攒证明、top-down 借权力。

写着写着又过十二点了。该睡了。思想锚点先固化下来，剩下的，明天接着推。

封面解读

这张封面是一则压缩了全文论点的视觉隐喻。

暗色里那道发光的墙 = 防火墙（可观测性）。 它护住身后的人，把所有甩锅与指责的箭挡在门外——对应第八节”先把己方打成铁桶，不让别人把锅甩过来”。

从单人汇聚、正被重新编织成网状系统的光丝 = 把不可替代性从人变系统。 过去所有依赖都长在一个人身上（XXX式的单点故障）；如今依赖被拆进一张自洽的网，不再需要任何具体的”钥匙人”——对应第四节的治本逻辑。

居中而平静的那个人 = 投资者姿态。 他不扛所有人，也不被所有人拖下水，只是安静地站在自己筑好的结构之后。这正是对抗逆淘汰的核心：不是更能干，而是更知道何时不该干。

一句话：封面的暗与光，说的不是绝望，是”不依赖平台、也不被平台吞噬”的从容——你把自己从单点变成了系统，把混乱挡在了墙外。

（以下为”变革兵法：趁热借势”核心要点，已并入正文第 7 节）

  • 危机借势（Crisis Leveraging）：平时推规范化 / 容器化 / CI/CD 卡点，他们嫌你”没事找事”；但当”月度测评 / 线上故障”这种所有人手忙脚乱的危机时刻，是唯一的黄金窗口。
  • 痛点就是切入点：趁他们被卡得生不如死，把容器化、自动化当”救命药”喂下去。
  • 用老板的焦虑借力打力：领导因测评焦头烂额时，把”P1 下压””禅道硬性度量”递上去，你不是推流程，是帮领导解围。
  • 封死退路，绝不妥协：方案一旦在危机中落地，就用流水线卡死，绝不让他们拖回泥坑。
