逆向淘汰：高效者的平台生存法则

2026-08-03T13:30:00.000Z2026-08-07T14:23:53.481ZChina

MindMap

前言

一次突发的代码评测任务，像一面照妖镜。

静态代码检测——听起来是个常规操作。但在我们这个平台部门，它变成了一场荒诞剧：其他小组因为平时拆活儿拆得细、人头冗余，轻轻松松搞起轮班制；而我们这个高度精简的两人核心团队，从检测开始到结束，全程焊死在机器上。

事情结束后我问自己一个问题：为什么高效的团队反而累死？

答案比我想的残酷。

1. 高效即原罪：平台的逆向淘汰

在这个平庸的平台生态里，高效不仅不是功臣，反而成了一种”原罪”。

平台部门并不奖励高效率。原本我的预期很单纯：提高单体效率，就能腾出时间做长远规划、做技术预研。但领导层的视角截然不同——当你把原本需要五个人干的活压缩到了两个人，他们看到的不是你高超的架构能力，而是：”你这里居然有富余的人手？那裁员就从你这个组开始吧。”

这不是某个领导的道德缺陷。这是成本中心的结构性悲剧：业务部门可以拿效率换利润，平台部门没有利润可换。省下来的时间不会变成奖金，只会变成裁员的信号。组织会计学的冷酷逻辑是——唯一能量化的不是你”少出了多少故障”，而是你”花了多少钱”。

反观那些毫无效能意识、写着垃圾代码的其他小组：一桩极简单的屁事拆给三四个人做，天天”工作量满满”；碰到紧急任务时，因为人头冗余，甚至能优哉游哉地搞起轮班。我们却在焊死自己。

这种现象有一个经济学上的名字——逆向淘汰（Adverse Selection）。在一个不按产出定价的系统里，低效能会系统性驱逐高能效。”制造问题再解决问题”的纵火消防员成了红人，”防患于未然”的守护者却成了精简的目标。

帕金森定律（Parkinson’s Law）在这里完成了它最恶毒的双向施展：劣币用它来膨胀工作量占据预算，良币用它来加速自我毁灭。

2. 剖析一：螺丝钉平台不需要英雄

这个平台从上到下，其实根本不需要能够优化系统、重构效能的”工程英雄”。它需要的，是按部就班、严守本分、彼此之间互不兼容的”螺丝钉”。

  1. 人肉卡点的岗位保全。 我们曾聊过，以前这里甚至有个专门”点 Jenkins 打包”的岗位——现在已经被测试顺手自动化了。这种荒谬岗位的存在，在平台的逻辑里是完全自洽的：一个坑代表一个预算，一个螺丝钉代表一份地盘。你不会因为消灭了一个无意义的岗位而获得奖励，你只会因此少了一个预算名额。

  2. 不兼容的知识垄断。 为了保住自己的坑，每个人都在”严守本分”地封锁知识。作为团队负责人，我发现底下组员连基本的打包部署流程都不知道，压根没操作过。而所有人——包括他们自己——都认为这种”各人只扫门前雪”的残缺状态理所当然。这不是懒政，这是理性选择：在一个奖励岗位保全而非价值创造的系统里，”知道得越少越安全”是最优策略。

  3. 热火朝天的垃圾循环。 我们这边用自动化几分钟打包完了，安静地下班；而其他组因为基础不牢，还在热火朝天地通宵修 Bug。在领导眼里，后者呈现出一派”工作量巨大、为公司鞠躬尽瘁”的虚假繁荣。前者呢？因为太平静，反而显得”没什么产出”。

当整个链条里每个环节都在为自己争取存在感的时候，制造浪费就成了创造价值。这不是阴谋，是系统性激励的结果。

3. 剖析二：判定标准的真空

根因在更上层——领导缺乏判定标准，完全依赖于汇报。

这不是能力问题，是组织基因问题。一个成本中心的负责人，他天然不具备衡量”不出事”的能力。可观测性搞好了一次故障都没发生——怎么算？代码质量提升后回归测试时间砍半了——体现在哪里？这些”正向产出”在报表上不可见。

唯一可见的是什么？加班时长。

所以这个系统不惩罚低效——它没有能力辨识低效。它唯一能辨识的，是”看起来忙不忙”和”汇报写得好不好”。这就完美解释了为什么纵火犯们能活得如此滋润：他们的产出链条是”制造问题→解决问题→贡献工时”，每一步都可量化、都可汇报、都”金光闪闪”。

错把活动量当产出，是管理懒惰的最高形式。

而当评测这种”上级压下来的政治任务”降临，系统会本能地将压力向效率最高的节点倾泻——因为只有那里，才真正有”把事做成”的能力。于是高效团队又双叒一次被精准收割。

4. 对策：冷酷的系统级自卫

我这人的性格注定不能坐以待毙。既然这个系统选择了劣币驱逐良币，那就必须启动最冷酷的系统级自卫。

  1. 第一，降频。 不要按照我们优化后的效率去报。很简单——没有这些工具之前，需要多少时间？帕金森定律不是单向的毒药，也可以是我们手里的盾牌。对外的交付节奏，拉回工具化之前的水平。省下的效率剩余，私有化——给自己做技术预研、做可观测性、磨技能。好的东西，在内部继续建、继续优化。不对外亮了。

  2. 第二，惜身。 我不是吃体力饭的。你看我像冤种吗？脑力劳动者的核心产出是判断力和设计力，不是”干了多少个小时”。”一人干三人的活”不是高效的证明，是把自己的稀缺资源当廉价工时卖。善良必须带上牙齿——能力是立身之本，不是作嫁衣用的。

  3. 第三，重构分工链。 1）XX需要从救急链里解放出来。过往不少明显不合理的决策，被多方同时催逼之下变成救急式答应——这不是项目，作为产品你会被过往决策长期影响。典型如”即使败絮其中，也要金玉其外”——跟某些上游对接时，对方不仅金玉不其外，连败絮都懒得遮。本该提供统一的接入口，结果需要根据他们返回的各种状态去转而调他们的各类子服务。几十行代码能解决的问题，已膨胀到近千行——代码即债务，每多一行适配逻辑就多一个潜在 Bug。更致命的是，负责对接的人被诸多救急任务频繁打断，既没精力反思这层不合理，也没精力去和上游来回 battle。于是”快速妥协”固化成持续收割，每次新需求都在这块腐肉上再贴一层创可贴。现在就要降低这种被同时催逼的频率，保证再发生时有缓冲。同时也要推进 Plugin 的可观测性建设，让各个 Plugin 自己吃自己的狗粮，别拿我们当碎催小工。2）YY这边，先慢慢熟悉系统的流程和逻辑，主动参与进来，不要再被轻易协调出去做其他事情。

  4. 第四，谁家孩子谁抱走。 烟囱口的位置决定了——问题没定位根因前，都是我们的问题。但我们的价值不是给各方兜底当小工，而是给各方提供快速反馈环境。本质上是”设计 Agent 的工作环境”，让问题能快速暴露、快速回流到制造问题的人那里。压力如果不回流，烟囱口就会被淤死。

后记

一个朋友知道这次评测的事后问我：”那你们怎么办？”

我说：从此不是”我们能干”，而是”我们知道什么时候不该干”。

台面上的人头一个都不会少。面上的节奏拉回原速。台面下的东西——自动化、可观测性、Lite 的重构——该建的继续建。只是不对外亮了。

这不是投机的伎俩，这是把被组织白白吃掉的效率剩余还给创造它的人。

《礼记》说”玉不琢，不成器”。能力是磨出来的，不是送给别人当垫脚石的。善良如果不带牙齿，就是邀请别人拿你当自助餐。

而我已经吃够自助餐了。

封面解读

这张封面是一个纯粹的视觉隐喻，没有文字干扰，完全依赖构图和光影来传达”逆向淘汰”的核心命题。

逆转的筛网/漏斗 = 逆向淘汰机制。 画面中央是一个倾斜到不自然角度的工业筛分装置，它的工作方向是颠倒的。这与正常世界中”筛选出优质、淘汰劣质”的逻辑完全相反——在这里，优质被筛除，劣质被保留。

明亮晶体坠入黑暗 = 高效者的被抛弃。 画面左侧和底部，锋利、明亮、完美的几何晶体正穿过筛网坠落，被下方冰冷的蓝黑色吞噬。它们发出的冷光在黑暗中显得格外孤独——这是效率与 excellence 在错误系统中的下场：不是被奖励，而是被精准地清除。

暗淡碎石堆积顶端 = 低效的虚假繁荣。 画面右侧，粗糙、暗淡、破损的石块堆积在漏斗顶端，被温暖的琥珀色机构灯光照着。这束光既不冷也不锐利，它柔和、包容、毫无评判——正如一个只认工时不认产出的系统，对低效的无限宽容。

冷暖光的割裂 = 系统的双重标准。 冷蓝与暖黄在同一画面中形成不可调和的对立。高效者被抛入冰冷的虚空，低效者沐浴在温暖的认可里。这不是偶然，是机制设计的结果。

锈迹金属 = 古老而顽固的组织惯性。 装置本身是暗沉的金属色，边缘带着铁锈。它看起来已经运转了很久，还将继续运转下去。它不会因为你发现了问题就停止——你只能选择不被它筛选出去。

一句话总结：封面用一台逆转的筛分机，压缩了全文的核心控诉：在错误的激励机制下，系统不是过滤器，而是垃圾桶——把好的一面朝下扔，把烂的一面留在表面供人观赏。

原始素材和基础语料（人工）

这次评测暴露了一些问题。平台部门并不奖励高效率。原本预期提高单体效率就能腾出时间做长远规划和技术预研，但领导层看来你有富余人手，裁员就从你这里开始。反观其他小组：一件事分几个人做，看起来工作量满满。过往还有个专门点 Jenkins 打包的岗位，现在被测试捎带手了。

这个团队不需要英雄，需要的是按部就班的螺丝钉。一个坑都不能少，彼此之间不兼容，没有 AB 备份。作为负责人，下面的人连基本打包流程都不知道，所有人觉得理所当然。碰到紧急情况，其他小组能搞轮换，我们两个人全程干到死。

对策：对外按优化前的效率报工作量，帕金森定律反过来用。周XX 要从救急链解放出来，推进 Plugin 可观测性。洪逐步熟悉 Lite，不再被轻易外派。谁家孩子谁抱走——我们的价值是提供快速反馈环境，不是兜底当小工。能力是自己立身的根本，善良必须带上牙齿。
