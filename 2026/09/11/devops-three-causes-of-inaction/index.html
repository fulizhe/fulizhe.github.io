不作为的三种病因：不为、不能与不知

2026-09-11T15:40:00.000Z2026-09-19T09:35:29.694ZChina

前言

今天下午在部门里，我撞见一件事。

测试的同事正在安排兼职运维的同学做”部署成功通知”——每次部署完成，群里就自动出一条消息。看起来是个很顺的流程。

我借这个势，多提了一句：既然部署成功都能通知，那打包开始前是不是也能通知一下？这件事在 DevOps 的闭环里本来就是一件事，也符合好莱坞法则——do not call me, I call you。

说完我就准备收工了。以过去几年的经验，这种话大概率换来一句”嗯，我们看看”。

结果她们的反应是：

“怎么我们之前没想到？”

那一刻，我比她们更意外。

1. 我以为她们懒

先把话说清楚：在那句话说出来之前，我对这件事的解释只有四个字，她们懒得做。

这个判断在我脑子里只占一个短句的位置，但它的后果很长。因为”懒”这个字，会直接决定我下一步的动作。

如果对方是懒，那你就不能给东西。给懒人一件工具，工具就会变成新的偷懒入口——通知滥发、告警刷屏、真出事了没人看。我在《纵火犯抱团之后》里写过那种场景：一条没有边界的通知，最后一定会演变成”谁都不看”。

所以我这几年的默认动作是：不提。

不是想不起来。是我怕那条通知最后变成一场告警风暴，卷回来砸我自己。我甚至在心里预演过完整剧本：我提了，她们顺手做了，但做得很糙，通知过量，群里怨声载道，然后有人问一句：”这不就是你先说的吗？”

这个剧本我准备了好几年。今天它没演。

2. 不是不为，是不知

“怎么我们之前没想到”这句话，我一开始是不信的。

我原以为”没想到”是一种体面的说法。真实情况多半是：想到了，但不打算做。

但她们接下来做的事否证了它。她们不但没想到，而且一说就懂，懂了还追问：还有哪儿也能这么干？

这里要拆开两个我过去一直混着讲的东西：

  • 不为：有能力、有资源、有待遇，但选择不做。这是意愿问题，杠杆是约束。
  • 不知：不是不想做，是从来没有人、也没有任何系统要求过她往这个方向想。这是认知问题，杠杆是点破。

我在《左移的反讽》里批判了三年的，是第一种人。他们有能力，拿着不低的待遇，有责任把事情做好。他们不动，是因为不想动。

测试是第二种。她们不动，是因为从来没有人问过她们。

放在一张表里，结构就出来了：

有能力 有资源 缺什么
研发 有 有 意愿
测试 有 有 一个理由

我这几年的绝大部分火力，都对着第一行。第二行从来没有进过我的视野。

为什么？因为测试在我的组织地图上，一直是盟友，不是改造对象。《左移的反讽》里我写过”盟友的嘴替我说，比我自己说重十倍”；推流程改进的时候，她们是支持者；推测试左移的时候，她们是受益者。盟友怎么会是问题？

今天才发现：盟友层也有没被打开的部分，只是它看起来不像问题。

3. 十年了，没有人问过她们那句话

真正让我坐不住的，是后来冒出来的一个数字。

我来这个部门三年。而她们，已经在这里快十年了。

也就是说：

十年了，没有人问过她们那句话——“你为什么不试着设计一下你自己的流程？“

不是没有人发现问题。是没有人给过她们这个提问。

这句话写下来的时候我后背有点凉。因为它同时解释了两件事。

第一，她们为什么”想不到”。

一个长期只被分配执行、从不被授予设计的岗位，是会萎缩的。她们被交办的活是：手工部署、替换文件、来回测。这些活有一个共同点——都是别人设计好了、你照着做。执行做十年，长出来的只有执行肌肉；设计这件事从来没落到过手上，那部分就是废用的。

我在《左移的反讽》里写过”测试是小工”。当时我用这个词，是指责研发把测试当小工使唤。我没想到的是，小工做久了，会真的不长设计师那根筋。这不是谁的恶意，是功能废用。

第二，我为什么没问。

一个来三年的人，对着在这儿快十年的老员工说”你们怎么早没想到”——这句话，我凭什么说得出口？

过去我给自己找的解释是：时机不到、优先级不对。今天要承认得更狠一点——我是不好意思。我资历最短，凭什么替一个比我早来七年的团队，指认他们没做过的事？

那十年的空白，前面是没人有权限问，后面是没人好意思问。中间正好卡着我这三年。

4. 为什么我等了三年才敢开口

“时机到了”这句话，最容易变成玄学。我想把它按实了说。

今天之所以能开口，是因为四件事同时成立：

  1. 可挂靠的同类事物已经在场。部署成功已经做到自动通知了。我不是在提一个新概念，只是把一件已经在跑的东西，往旁边挪了一格。
  2. 成本的承担者已经存在。兼职运维已经在做这件事，方案甚至不需要新增人力。
  3. 这句话是”顺手”，不是”主张”。我不是在开会提案、要资源、要排期，我只是在一个人已经在做 A 的时候，补了一句”B 也一样”。
  4. 基础条件已经铺好。打包早就自动化了。三年前我刚下来的时候，她们还在手动打包。那时候提”打包通知自动化”，对方要解决的不是通知问题，是打包问题，我的建议只会变成一个不合时宜的空谈。

四条门槛，三年前 0/4，今天 4/4。

所以我这三年不是”犹豫了三年”，是门槛真的没齐。这一点对我很重要——它把”我为什么不说”从一个人格问题，改成了一个条件问题。

我过去觉得”顺势而为”是个很软的说法，像是给不行动找的台阶。现在觉得它很硬：它是一张门槛检查表。门槛不齐时说出来的话，不叫顺势，叫提前替人着急。

5. 我说：别听我的

今天最后我做的一件事，是对通知的形式提了个意见——现在那条消息空格太多，看着一大片，信息密度很低。

然后我加了一句：这只是参考，你们按自己的诉求来，别被我干扰。

听起来只是客气。但它是我今天唯一想留下来的动作。

因为这份通知的使用者，是她们，不是我。

我得承认：这件事我判断不了。我拿起那条消息，看到的是信息密度不够；她们拿起同一条消息，判断的是”扫一眼能不能拿到此刻要的东西”。标准长在她们的使用现场，不长在我的审美里。

所以我在这儿只有建议权，裁定权本来就不在我手上。

再往里一层，还有个更实际的理由：她们已经在按自己的需要迭代了。

我今天给了个起点，她们已经开始往外长。那我此刻要是把形式定下来，会发生什么？标准就闭合了——剩下的事从”探索”降级成”执行”，迭代当场终止。她们会退回去当接受者，只不过这次的接受对象，从研发换成了我。

所以”别听我的”这四个字，保护的不是她们的情绪，是这个迭代过程还活着。

这也跟我一直在讲的”谁家孩子谁抱走”是同一件事：决定权应该放在后果落下的地方。排版好不好，落在读它的人身上，那就该由读它的人定。

我给启动成本，不给最终答案。

启动成本——“这件事可以做到流程里、自动触发”——是她们真缺的那块。从零起步最贵，我替她们付了这一笔。最终答案——具体长什么样——是她们真不能要的那块。要了，她们就永远是接受者。

后记

写到这里我发现，这篇文章的主角其实不是那条通知。

我原本是来记录一次”归因翻案”的：我以为她们懒，其实她们只是没被问过。但写着写着，翻案的对象变成了我自己——我以为自己是那个看得比较清楚的人，结果在这一格上，我十年都没睁过眼。

我常说自己对别人不抱期待，失望太多次了。写这篇的时候想明白一点：”不抱期待“和”预设有敌“不是一回事。前者让我轻装，后者让我瞎。今天最该记住的，是我带着”她们会偷懒”的剧本上场，结果剧本没演——反面力量没来，来的是一句诚心诚意的”怎么我们之前没想到”。

至于那条通知最后会长成什么样，我不知道，也不该由我定。下次打包的时候，我在群里看它一眼就行。

封面解读

这张封面是一组同一面墙上的三扇门，一眼看去完全一样：同样的尺寸、同样的间距、同样的混凝土墙面、同样的冷灰蓝。这个”一样”是刻意的——三种不作为在表面上长得完全一致，都是一动不动。真正需要被分诊的，是它们各自因为什么而打不开。

左门 = 不为。 一根锈迹斑斑的钢制横闩压住门板，上面挂着一把沉甸甸的挂锁，锁是从外面扣死的。这扇门不是打不开，是有人明确决定不让它开。对应到组织里，就是那种有能力、有资源、有待遇，但选择不动的人。对付它只能用约束——你无法用一句问话解开一把别人有意扣上的锁。

中门 = 不能。 门框被压变了形，门板歪斜，门缝里卡着撬棍、锤子和一堆碎料，门根本合不拢也开不了。这扇门的失败不是意愿问题，是工具问题——它卡住的地方，恰好是需要外部提供支撑的地方，光靠它自己动不了。

右门 = 不知，也是整张图的焦点。 它完好、干净、微微虚掩，一道柔和的青白色光从门缝里漏出来——它是这个画面里唯一的光源。但看它前面的地面：一层完整的、均匀的细灰，没有脚印，没有拖痕，没有任何人走过去的痕迹。

这扇门一推就开，而它是三扇里唯一一个从来没有人走到过跟前的。

这就是文章真正的发现。那些看起来像”不作为”的沉默，有一部分根本不是拒绝，是从来没有人给过那句提问。光一直在那里，门也一直没锁——只是一直没有人过来敲一下。

画面里还画了很细的、蓝图式的测量线和标注线，出现在每扇门的周围。它们不指向任何数字，只指向分类——这正是这篇文章在做的事：先把不作为分类，再谈用什么杠杆。用冷色而不是暖色，也是同一个意思：这不是一场控诉，是一份分诊报告。

原始素材和基础语料（人工）

今天在公司发生了这样一组对话：我看着部门内的测试人员在让兼职运维人员做部署成功的通知，于是借势向她们建议既然你都部署做通知了，那你们之前每次打包开始前都要在群里通知下，这个通知也可以这么来啊。其实这个在 devops 流程体系下就是闭环，也符合好莱坞法则, do not call me, i call you。我过往一直不提是害怕出现类似告警风暴的场景导致出现反面力量，但意料之外的是测试人员居然非常高兴 —— 怎么我们之前没想到；但对于我来说，他们的没想到反而是我最大的没想到；过往我以为他们是因为懒得这么做才选择自己手动在群里通知的，万万没想到他们居然是真的没有这个能力做到这个意识。

我过往的这些博文，你列举出来的这些，其它绝大部分都是针对研发的，我认为他们有能力，而且拿着高级的待遇，他们有责任，有义务，有能力做到；而今天让我意外的是测试。

这三年是我来这个部门三年，她们过往已经快十年了…… 不会有人去问那句关键的话：”你为什么不主动设计一下你自己的流程？” 我喜欢这句。他们配出了”打包开始自动通知”，她们是让人做这个。为什么改革的第一块砖必须从测试撬——因为它是唯一会真心接受改造的一层。我也喜欢这个。我现在对自己之外的人不报期待，失望太多次了。一来我的诧异更多是时机到了，可以说出口，之前一穷二白说了也不管用，因为还有大量更重要的事情排在前面，例如我刚下来的时候它们还是手动打包……盟友层需要升级，成本比纠偏低一个数量级，这个倒确实是的，但依然只能是顺势而为。

“做进流程、自动通知” 这个本身就是我建议她们的。

“流程开始前 + 结束前”这两个通知点是我提的，她们开始根据自身需要去迭代。比如我之前担心的告警风暴，而且我强调告诉她们：根据你们自己的诉求来，对于通知形式我的意见只是参考，不要被干扰。

这个通知形式的形式是基于自动化流程的，我只是觉得当前通知消息之间空格太多，导致看着很多，信息量低，我不希望她们被我干扰，过去她们是手动在群里发消息……这个不算生产权吧。

我主要考虑到因为她们是主要使用者，我不是。

续补记录（成文过程中新增或改写的观点，供事后回溯）：

1、”三种病因”这一分诊框架（不为 / 不能 / 不知）为成文时新增，原始讨论中是零散出现的”动机问题 / 认知问题”，此处收敛为三分法，并把”不知”的实质追加界定为”从未被授权去想”。

2、第 3 节”我为什么没问”一段里”我是不好意思”这句自省为成文时新增——原始对话只谈到”时机不到、优先级不对”。

3、第 4 节的四条门槛（可挂靠的同类事物已在场 / 成本承担者已存在 / 这句话是顺手而非主张 / 基础条件已铺好）由讨论中的清单整理成明文，并补上”三年前 0/4、今天 4/4”的对照。

4、第 5 节”我给启动成本，不给最终答案”为成文时归纳的新表述；其依据是原始素材中”我的意见只是参考”与”她们是主要使用者，我不是”两句。

5、后记中”不抱期待 / 预设有敌”的区分，以及”我带着她们会偷懒的剧本上场，结果剧本没演”，为成文时新增。

  • 显性支出来自个人，隐性收益归公：降摩擦工程为什么总输给"问一下就完了" — "问一下就完了"的隐性成本，本文第 5 节的账是它的续篇
  • 医者不自医：IT团队的“人肉API”与伪自动化的形式主义 — 人肉 API 与伪自动化，对应本文"通知该由系统做、不该由人做"
